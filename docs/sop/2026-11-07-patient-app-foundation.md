# SOP: Patient app foundation (`apps/patient`)

| | |
|---|---|
| **What shipped** | A new workspace app `apps/patient` ("Oakly Health"): boots to a real **Login** (email + password through `@oakly/api-client`), and once signed in a **placeholder Home** that shows the user from `GET /auth/me`, with **Log out** that clears the keychain and the query cache. Shell only, no ported screens. |
| **Branch / commit** | `feature/patient-app-foundation`, cut from `oakly/main` `312eaa5`. Not pushed. |
| **Device-verified?** | **No.** Jest only (RNTL against a fake `fetch`); the app was not built, run in a simulator, or called against a live backend. |

## Why
The 2026-11-07 audit (`LEDGER-patient-audit.md`) found the old patient app (Expo SDK 53, off-org repo, hand-typed axios, tokens in MMKV with a hard-coded key, a committed keystore in history, refresh deadlock, no tests) about 35% working end to end. The owner chose to move it into this monorepo on SDK 57 rather than hop five SDKs, copied **without git history** so the committed signing material is not carried over, using the generated api-client so route/shape bugs become compile errors.

## How
| Area | Decision |
|---|---|
| Versions and tooling | Same Expo / RN / React / jest-expo / eslint versions as `apps/caregiver`, so the lockfile only gains the new importer and nothing resolves twice. CI (`pnpm -r --if-present typecheck / lint / test`) picks the app up with no workflow change; the api-types drift check is unaffected (no spec change). |
| Shell copied, not extracted | `src/auth/session.ts` (state machine, single-flight refresh), `secureStorage.ts` (expo-secure-store, `AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`), `api/{client,config,queryClient,unwrap}`, theme tokens and the font setup are copies of the caregiver app's. A shared package was rejected for this slice (scope, and the two apps' theme is about to diverge); it is a follow-up. |
| Refresh | The refresh call uses its own client with no bearer and no retry hook, so a **401 on the refresh itself is a verdict: sign out**, never a request queued behind the running refresh. Offline or 5xx keeps the session and surfaces the original 401. Tested through the real client. |
| Sign-in | `POST /auth/login/mobile` (`email_or_phone` carries the email), then one `GET /auth/me` with the new token **before** the session opens. A non-patient account is refused without ever being signed in, so Login stays mounted and shows why (opening the session first swaps the screen out and the error is lost; found by a test). |
| Gate | Pure `resolveGate`: loading, error (retry / sign out), signed out, wrong account, **verify email (placeholder message, the verify screen comes in P3)**, app. |
| Logout | `session.signOut()`: clears memory, secure-store (access, refresh, reserved push key) and, through `onSignedOut`, the whole React Query cache. No server logout route exists. |
| Identity | Name "Oakly Health", slug `oakly-patient`, iOS bundle id and Android package `com.oakly.oaklypatient` (never published), URL scheme **`oaklypatient`**. The scheme is a choice made here; the password-reset email still links `oaklycare://reset-password?token=`, so the reset deep link (scheme in the email template vs this one) is decided in P3. `supportsTablet: false`. |
| Left out on purpose | MMKV, any hard-coded encryption key, `android/` and `ios/` (generated by prebuild, gitignored), keystores and gradle properties, `.env` (only `.env.example`, no secrets), push, location, camera and the other native modules (added with the slice that needs them). |
| Test-only helper | React Query keeps 5-minute gc timers that `queryClient.clear()` does not cancel when a screen is still mounted, which kept the jest worker alive; `disableCacheGcForTests` (test-utils) turns gc off per test file, app defaults untouched. |

## Verification
- `pnpm typecheck` and `pnpm lint` for the app: clean. `pnpm api:generate` then `git diff --exit-code` on `schema.d.ts`: no drift.
- Jest, single worker (`jest -w 1`), foreground, **no `--forceExit`**: 4 suites, 29 tests passed and the process exited. Tests: gate decision table; session state machine (restore, single-flight refresh, rejected refresh signs out, offline keeps session, sign-out wins a race); App boots to Login; form validation sends nothing; email + password sign-in shows the user from `/auth/me` and logout empties the keychain, session and query cache; wrong password; caregiver account refused without a stored session; stored session restored; **401 on the refresh call logs out without hanging**; refresh 5xx keeps the session; good refresh rotates tokens and retries once.
- Test bodies are typed against `Schemas` with placeholder values; none is a captured live response, so this is **not** an FE integration guide.
- **Not verified:** a simulator or device, the fonts and splash on screen, a live login against the backend, Android.

## Operate / roll back
`pnpm patient` (set `EXPO_PUBLIC_API_URL` in `.env.local`). Revert the branch to remove the app; nothing else depends on it. No backend change.
