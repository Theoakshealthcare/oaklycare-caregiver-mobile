# SOP: Caregiver onboarding matches the Figma exports

| | |
|---|---|
| **What shipped** | The caregiver welcome slides, sign-up, code screen, account-created page, login, password recovery, setup steps 1-3, consent and a new "Profile Setup Completed" page now follow the Figma exports in `ss/caregiver` (frames 8.12.02 to 8.14.21). One reusable green toast. The identity (KYC) step is switched on in the staging (`preview`) build. |
| **Branch / PR** | `feat/caregiver-onboarding-parity`, monorepo PR (see the PR for the number). |
| **Why** | The owner's first real-phone test of the caregiver app found the onboarding different from Figma. The read-only audit is `ledgers/PARITY-caregiver.md` (section E and F); this change closes those rows. |
| **Not verified** | **On a device.** Jest, `tsc --noEmit` and ESLint only. Nothing was run on a simulator or phone; the lead builds the APK. Layout, spacing, colours and the number pad behaviour of the new code boxes all need an owner look. |

## How (and what was decided)
| Area | What changed | Decision / reason |
|---|---|---|
| Welcome slides | Four slides in the Figma words; slide 3 (Oakly FallGuard™) on the coral panel with `onboarding-3.png` (copied from the patient app, 362 px wide, so a little soft on a 3x phone). **Get Started on every slide opens sign-up** (it used to scroll to the next slide). Both headline lines are the same size. "Already have an account ? Login" as drawn. | The earlier caregiver-only copy ("Care work that comes to you") and its test were replaced on the owner's instruction (exact parity). |
| Toast | `components/ui/toast.tsx`: `showToast(message)` plus one `<ToastHost />` mounted in `MainApp` above the navigator. Green, 3 s, a newer toast replaces the old one. | It lives above the navigator so it survives the stack swap that follows a login. Used for "Login Successful", "Email Address Verified" (only when a signed-in person verifies from the gate) and "Password has been Reset Successfully". "Payment Details has been updated" is not wired (bank screen is another scope). |
| Sign-up | Fields Full Name, Email Address, Create Password (the optional phone box is gone); terms line "By tapping Get Started, ..."; ticked box is teal with a white check; Cookies Policy is underlined bold. The password eye now shows the crossed eye while hidden (`components/ui/input.tsx`, so every password field in the app). | Phone-number sign-in stays off (owner), so the field label stays "Email Address", not "Email Address/Phone Number". The box is **not pre-ticked** (Figma pre-ticks it): pre-ticked consent is not valid consent. |
| Code screen | `components/ui/otp-boxes.tsx`: five boxes typed with the phone's own number pad (focused on arrival, a pasted or auto-filled code spreads over the boxes, Backspace on an empty box goes back). The hand-drawn keypad is gone. "Didn't receive a code ?" (typo fixed) and a "Resend Code" pill. No Verify button: the fifth digit verifies; the button comes back only after a network failure that kept the typed code (the 2026-11-23 owner fix). | Figma's keypad frame is the iOS keyboard, not a screen element. |
| Account created | Green check illustration (`success-illustration.tsx`, plain views, no asset), Figma title and body, **Set up your Account**, Close. "Set up your Account" signs in with the sign-up e-mail and password kept **in memory only** (`auth/pendingSignIn.ts`, handed out once, cleared on sign-out/restart) so the gate opens the setup straight away; if that fails or the app restarted it opens Login. | Figma goes straight on to setup; verification issues no tokens, so a sign-in is needed. |
| Login | Toast on success, "Forgot Password" in bold dark (the Figma "Forget" typo is not copied). | No OTP step and no phone sign-in (owner). |
| Recover password | Subtitle "Provide your email address to recover your password", button "Send Recovery Link", then a new **RecoverCode** screen ("Verify Email Address", five boxes), then **Reset Password** with only the two password fields ("Reset your Password"), then the green toast and Login. | The server checks the emailed code together with the new password, so the code screen only collects it. A wrong, expired or exhausted code is reported by Reset Password with an alert and sends the caregiver back to an emptied code screen. The "Email Address Verified" toast after the code is **not shown**: nothing has been verified at that point, and a toast saying so would be untrue. The "signed out on your other devices" notice that was in the old success alert is gone with it. |
| Setup steps | Header "Set up your Account", sub-line "Set up your account in N steps" (N is 4 with the identity step on, 3 with it off), small grey "Step N" label over a thin bar that fills a quarter per step. House address is a single line. | Figma's own bar widths are inconsistent (24 %, 64 %, 100 %); quarters were used as the owner asked for four steps. Step 2's placeholders keep the code's "Select your Specialization" etc.; Figma repeats "Select your Gender" on every dropdown (copy-paste slip). |
| Identity step | Header, step bar and "Identity Verification" title; two Figma rows **Scan identification** ("National ID, Passport, or Driver's License", the two Figma typos fixed) and **Face Scan Verification** ("Turn on your Camera") over a grey **Save & Continue**. Both rows start the same hosted Dojah check (the hosted page takes the ID photo and then the selfie); they stay off until the separate identity consent box below them is ticked. All the other states (checking, verified, try again, under review, unavailable ...) are unchanged. | The app has no native scan screens (the check is the backend-hosted page), so the Figma "Document Scan" and "Face Scan" camera frames are not built. The separate, never-pre-ticked identity consent (design 10.2) is kept under the rows. |
| Consent | Heading "Background Checks & Data Usage Consent", the terms line only, button **Give Consent**, no step bar. | The two extra paragraphs and the step bar are removed because Figma has neither. The old paragraphs can be restored from git history if the owner wants them back. |
| Profile Setup Completed | New page (`ProfileSetupCompleted.tsx`): green check, "Profile Setup Completed", "Your Profile verification is under review, you will be notified in 24hrs." ("uploaded" fixed), **Go to Homepage** ("Homeoage" fixed), Close. Shown once after the server accepts the consent, before the status screen. | The gate is driven by the server's status, which flips to `under_review` at once. `onboarding/setupSubmitted.ts` is an in-memory flag the consent screen raises; while it is up the navigator shows this page for an `under_review` profile, and Go to Homepage / Close lower it. A relaunch goes straight to the status screen. "Go to Homepage" opens the status screen, because an unapproved caregiver cannot reach the app. |
| Staging build | `EXPO_PUBLIC_KYC_MODE: "api"` added to the `preview` env in `apps/caregiver/eas.json`. | Staging already has the Dojah settings and `KYC_RETURN_URL` equals the app constant. Voice notes: `EXPO_PUBLIC_VOICE_NOTES: "live"` added to the same `preview` env on 2026-11-23 (owner asked for a live test; staging's `VOICE_NOTES_ENABLED` is on since backend #69). A real phone recording is still unproven. |

## Operate / roll back
Revert the PR. To make the terms line name the real button again, change `TERMS_ACTION` (CreateAccount) and `CONSENT_TERMS_ACTION` (ConsentScreen). To turn the identity step off in staging, remove the env line and rebuild.
